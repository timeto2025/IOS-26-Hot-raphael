# RaphaelOtgLatchDxe — принудительное включение OTG VBUS в UEFI

**Статус: UNTESTED.** Код написан, но ещё не собран и не прошит. Ничего из этого
не выполнялось на телефоне.

## Что это и зачем

Под Windows закрытый драйвер Type-C/зарядника Qualcomm не поднимает повышающий
преобразователь 5 В (OTG VBUS), поэтому USB-OTG-устройства без своего питания не
работают. Сам буст живёт в контроллере заряда `pm8150b` (периферия DCDC) и
управляется по шине SPMI.

Драйвер включает буст **из UEFI, до загрузки Windows**, прямой записью в регистры
`pm8150b`. Результат не зависит от того, что делает драйвер ОС: буст поднят на
уровне железа раньше него.

Это «софтовая» последовательность OTG, та же, что в mainline
`qcom_usb_vbus-regulator.c` для `qcom,pm8150b-vbus-reg`:

1. `OTG_CFG` (0x1153): сбросить `OTG_EN_SRC_CFG` (BIT1) — снять VBUS с аппаратной
   привязки к CC/ID, отдать управление софту.
2. (опц.) `OTG_CURRENT_LIMIT_CFG` (0x1152): лимит тока источника (по умолчанию 1500 мА).
3. `CMD_OTG` (0x1140): поставить `OTG_EN` (BIT0) — буст включён.

Запись идёт по SPMI PMIC-arbiter v5 напрямую (MMIO). Все адреса регионов и формат
транзакций взяты из DTS самого raphael (`sm8150.dtsi`) и из mainline
`spmi-pmic-arb.c` / u-boot `spmi-msm.c`:

| регион | адрес | назначение |
|---|---|---|
| core   | 0x0C440000 | версия арбитра, число APID, карта PPID→APID @ 0x900 |
| chnls  | 0x0C600000 | каналы записи, шаг 0x10000·apid |
| obsrvr | 0x0E600000 | каналы чтения (observer), шаг 0x80·apid, ee 0 |
| cnfg   | 0x0C40A000 | таблица владельцев @ 0x700, владелец = regval & 7 |

Защёлка выполняется по событию **ReadyToBoot** — в самый последний момент перед
передачей управления ОС, чтобы ни один драйвер UEFI не сбросил `OTG_EN` после нас.

## ⚠️ Правило эксплуатации (важно)

Это **одноразовая защёлка**: буст остаётся включён до сброса или перезагрузки.
**Не подключайте зарядку, пока буст защёлкнут** — на линии VBUS окажутся два
источника 5 В. Защиты `pm8150b` (OTG OVP/OCP), вероятно, вырубят буст, но
полагаться на это нельзя. Хотите зарядиться — перезагрузитесь (или дождитесь
будущей CC-зависимой версии, которая гасит буст при появлении зарядника).

## Интеграция в сборку (mu_aloha_platforms, SurfaceDuo1Pkg)

Все пути — от корня рабочей области UEFI.

1. Скопировать драйвер в дерево (рядом с другими исходными DXE, напр. `SimpleFbDxe`):

   `cp -r uefi/RaphaelOtgLatchDxe Platforms/AndromedaPkg/Driver/RaphaelOtgLatchDxe`

2. Добавить в сборку платформы (чтобы edk2 его скомпилировал). В
   `Platforms/SurfaceDuo1Pkg/SurfaceDuo1Pkg.dsc` (или общий `.dsc.inc`,
   где перечислены `[Components]`) добавить строку:

   `AndromedaPkg/Driver/RaphaelOtgLatchDxe/RaphaelOtgLatchDxe.inf`

3. Включить в прошивку raphael (FV). В
   `Platforms/SurfaceDuo1Pkg/Device/xiaomi-raphael/DXE.inc` добавить строку
   **после** `SPMIDxe` (стр. 66):

   `INF AndromedaPkg/Driver/RaphaelOtgLatchDxe/RaphaelOtgLatchDxe.inf`

   Порядок в `DXE.inc` не задаёт порядок запуска — драйвер и так срабатывает по
   ReadyToBoot, то есть позже всех. Трогать `APRIORI.inc` не нужно.

## Сборка, прошивка, откат

- Собрать UEFI как обычно (workflow сборки mu_aloha для raphael, вариант `_NOSB`).
- **Сначала сделать резервную копию текущего раздела, куда шьёте UEFI** (напр.
  `recovery`), и только потом прошивать — по правилу «бэкап перед каждым flash».
- Прошить новый UEFI тем же способом, что и раньше.
- **Откат:** прошить обратно прежний образ UEFI. Драйвер не трогает разделы и
  userdata — откат полный.

## Как увидеть лог

**Без UART (основной способ):** драйвер пишет весь лог в файл **`raphael-otg.log`**
в корень каждого FAT-тома (то есть на раздел `esp`). После загрузки смонтируйте
`esp` из Arch и прочитайте файл:

```
sudo mount /dev/disk/by-partlabel/esp /mnt/esp && cat /mnt/esp/raphael-otg.log
```

Ключевые строки: `owner EE N` (владелец APID зарядника), три строки `write EFI_*`
(прошла ли запись и её статус) и `readback ... OTG_EN=? -> VBUS LATCHED ON/off`.
Это однозначно покажет, где затык: нет доступа на запись (владелец/EE), запись не
прошла (статус), или бит не удержался (перебивание).

**Через UART:** те же строки `RAPHAEL-OTG:` идут в консоль UEFI. Ожидаемое на успехе:

```
RAPHAEL-OTG: PMIC-arb version 0x5....
RAPHAEL-OTG: charger PPID 0x211 -> APID NN, owner EE 0
RAPHAEL-OTG: off 0x53 0x.. -> 0x..
RAPHAEL-OTG: off 0x40 0x.. -> 0x..
RAPHAEL-OTG: CMD_OTG readback 0x.., OTG_EN=1 (VBUS latched ON)
```

## Честные риски (проверяются на первом тесте)

1. **Владение APID (EE).** v5 принимает запись только от EE-владельца APID. Драйвер
   это проверяет: если зарядник принадлежит не EE0, он напишет
   `charger APID owned by EE N` и **ничего не запишет**. Android пишет OTG с
   апсового процессора, так что EE0, скорее всего, владелец — но подтвердит лог.
2. **Маппинг MMIO.** Если доступ к регионам PMIC-arb вызовет исключение, значит
   регион не в карте памяти UEFI на этапе ReadyToBoot — тогда добавить диапазоны
   как device memory (UC) в карту платформы или через `gDS->AddMemorySpace` +
   `SetMemorySpaceAttributes`.
3. **Перебивание драйвером ОС.** Если Windows при инициализации своего Type-C всё же
   сбрасывает `OTG_EN`, защёлка на уровне UEFI не переживёт — тогда потребуется
   CC-зависимая версия уже под Windows (следующий, более сложный этап).
4. **Зарядка при включённом бусте** — см. правило эксплуатации выше.
